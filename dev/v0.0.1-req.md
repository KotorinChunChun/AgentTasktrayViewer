Windows用のタスクトレイ常駐アプリを作ってください。

CodexとClaude Codeの使用量の残りを、Windowsのタスクトレイアイコンに常時表示するアプリです。

アプリ名は AgentTasktrayViewer です。

# 最重要要件

タスクトレイには以下の4種類のアイコンを用意してください。

1. Codex：5時間枠
2. Codex：週間枠
3. Claude：5時間枠
4. Claude：週間枠

初期状態では4つすべて表示してください。

ただし、それぞれのアイコンは右クリックメニューから個別に表示ON/OFFできるようにしてください。

専用の設定フォーム、メインフォーム、設定ウィンドウは作成しないでください。

日常的な設定・操作はすべてタスクトレイアイコンの右クリックメニューだけで完結させてください。

独自判断で別のインストーラー方式へ変更しないでください。

# Codexの使用量取得

Codexデスクトップアプリがインストールしている実行ファイルを使用してください。

以下を再帰的に探して `codex.exe` を見つけます。

%LOCALAPPDATA%\OpenAI\Codex\bin

複数見つかった場合は更新日時が一番新しいものを使用してください。

環境変数

CODEX_CLI_PATH

が設定されている場合は、そちらを最優先してください。


## Codex app-server

見つけたcodex.exeを

app-server --stdio

引数付きで子プロセスとして起動してください。

ウィンドウは表示せず、標準入力・標準出力を使ってJSON-RPC通信します。

送信するメッセージは基本的に次の3つだけです。

1. id=0
   initialize

   clientInfoにこのアプリの名前とバージョンを入れる

2. initialized
   idなしのnotification

3. id=1
   account/rateLimits/read

応答から各rate limit windowについて以下を取得してください。

- usedPercent
- windowDurationMins
- resetsAt

resetsAtはUnix秒としてローカル時刻に変換してください。


# Codexの枠判定

windowDurationMinsによって分類してください。

- 300 → 5時間
- 10080 → 週間

primary / secondaryというプロパティ名自体に5時間・週間という意味を持たせないでください。

必ずwindowDurationMinsを確認してください。

返ってくる枠の数や順番が将来変化しても可能な限り壊れない実装にしてください。

片方しか取得できない場合でもアプリ全体は正常動作させてください。


# Codex取得処理

- 15秒でタイムアウト
- 終了後は子プロセスを確実に終了
- Process.Disposeを行う
- 同時に複数の取得処理を走らせない
- 読み取り専用メソッドだけを使用
- Codexへ設定変更や作業実行を行わない
- LLMへのプロンプト送信を行わない
- 使用量確認そのものによってCodex使用量を消費しない


# Claude Codeの使用量取得

Claude Codeについては、認証ファイルやブラウザCookieを直接解析しないでください。

Claude CodeのstatusLine機能から渡されるJSONを利用してください。

以下の値を利用します。

rate_limits.five_hour.used_percentage
rate_limits.five_hour.resets_at

rate_limits.seven_day.used_percentage
rate_limits.seven_day.resets_at

それぞれ

- used_percentage
- resets_at

を読み取ってください。

resets_atはUnix秒としてローカル時刻へ変換してください。


# Claude statusLine受信モード

同じexeを通常常駐モードとstatusLine受信モードの両方に使用できるようにしてください。

通常起動:

App.exe

statusLine受信モード:

App.exe --claude-statusline


# --claude-statusline の動作

Claude Codeから標準入力で渡されたJSONを読み取ります。

そこから

- rate_limits.five_hour
- rate_limits.seven_day

だけを抽出してください。

%APPDATA%\アプリ名\

配下にClaude使用量キャッシュとして保存してください。

保存してよい情報は以下のみです。

- used_percentage
- resets_at
- 取得日時

以下は保存しないでください。

- 認証情報
- プロンプト
- 会話内容
- transcript_path
- 作業ディレクトリ
- その他使用量表示に不要な情報

statusLine処理は可能な限り短時間で終了してください。


# 既存Claude statusLineへの配慮

~/.claude/settings.json

にすでにstatusLine設定が存在する可能性があります。

既存設定を勝手に削除・破壊・上書きしないでください。

既存statusLineが存在する場合は、

- 既存statusLineを維持する
- 本アプリにも同じJSONを渡せるラッパー方式を検討する
- 安全に共存できる仕組みにする

ことを優先してください。

自動変更を行う場合は必ず元設定をバックアップしてください。

既存環境を安全に維持できない場合は、勝手に書き換えず、右クリックメニューからユーザーが明示的にClaude連携を有効化する方式としてください。


# Claude使用量の鮮度

Claude CodeからstatusLineへ通知された最新値を使用してください。

使用量更新だけを目的として、

- Claudeへダミープロンプトを送信する
- `/usage`を自動実行する
- AIモデルを呼び出す
- APIリクエストを発生させる

といった処理は行わないでください。

Claude Codeから新しいstatusLineデータを受信したら、定期更新タイマーを待たずに即座にClaudeのアイコンを更新してください。

表示をOFFにしたことを理由にUsageProviderそのものを破棄しないでください。


# アイコンの基本デザイン

アイコンには「残り%」を整数で表示してください。

計算式:

remainingPercent = 100 - usedPercent

値は0～100にClampしてください。

小数の場合は表示用に整数へ丸めてください。

32×32ピクセルを基準とした角丸四角形とし、その中央に数字を大きく表示してください。

100の場合も収まるよう、文字数に応じてフォントサイズを調整してください。

暗いWindowsタスクバーでも見やすいよう、

- 高コントラスト
- 太めの数字
- 明るい文字
- 明確な背景色

としてください。

# 使用量警告表示

サービスと枠を識別する背景色は維持したまま、使用率が高い場合は外枠で警告してください。

「今すぐ更新」を押した場合:

その場で

を実行して最新値を取得してください。

# 使っていない間は更新を止める

既定はONです。

Codexについて、

配下のJSONLファイルが15分以上更新されていなければ、Codexを使用していないと判断して定期取得を停止してください。

- フォルダが存在しない
- アクセスできない
- 更新日時を取得できない
- 判定不能

判定できないために古い値を延々と表示する動作は避けてください。

Claude側のstatusLine受信処理は、この設定によって停止しないでください。

# 二重起動防止

Mutexを使って通常常駐モードの二重起動を防止してください。

ただし

App.exe --claude-statusline

はClaude Codeから何度も起動される可能性があります。

そのため、通常モード用MutexによってstatusLineモードを拒否してはいけません。

statusLineモードは、

1. stdinを読む
2. 必要項目だけ抽出
3. キャッシュ更新
4. 常駐プロセスへ更新通知
5. 即終了

という軽量構成にしてください。


# 常駐プロセスへのClaude更新通知

--claude-statusline

で新しいデータを受け取ったら、常駐中のプロセスへIPCで通知し、Claudeの2つのアイコンを即座に更新してください。

方式はシンプルなもので構いません。

候補:

- Named Pipe
- Named Event
- その他のローカルIPC

常駐プロセスが起動していない場合はエラー扱いにせず、キャッシュを書いて正常終了してください。


# リソース管理

NotifyIconを最大4個使用するため、終了時には全アイコンについて確実に

Visible = false
Dispose()

を行ってください。

動的に生成する以下のリソースも適切にDisposeしてください。

- Icon
- Bitmap
- Graphics
- Font
- Brush
- Pen

アイコンを更新するたびに古いIconを適切に破棄してください。

長時間常駐してもGDIハンドルやメモリ使用量が増え続けないようにしてください。


# エラー耐性

CodexとClaudeは完全に独立して動作させてください。

例えば

- Codex取得失敗
- Claude未設定
- Claudeの5時間枠だけ取得できない
- Codexの週間枠だけ取得できない

といった状態でも、取得できた他の枠は正常表示してください。

例:

Codex 5時間 → 82
Codex 週間 → ?
Claude 5時間 → ?
Claude 週間 → 74

どれか1つのエラーによってアプリ全体を終了させてはいけません。

# 実装品質

以下を重視してください。

- nullableを適切に扱う
- JSON項目欠落で落ちない
- Unix時刻変換を共通化
- UIスレッドをブロックしない
- async/awaitを適切に使う

- UsageProviderを単体テスト可能にする
- ProviderとUIを疎結合にする
- 使用率0%
- 使用率100%
- 取得不能
- 片方だけ取得
- statusLine未設定
- 非表示→再表示
- 最後のアイコンをOFFにしようとするケース
